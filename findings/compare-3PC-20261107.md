# BK-collect comparison: PC-A, PC-C, PC-B

Reports: `BK-report-PC-A-20261107-0155.zip`, `BK-report-PC-C-20261107-1114.zip`,
`BK-report-PC-B-20261107-1411.zip`. Generated table: `BK-compare-report.md`. Compared 2026-11-07.
Supersedes the two-PC `compare-PC-A-vs-PC-C-20261107.md` (still valid for those two).

## Verdict

The three game installs match except for one file. Same RelicCOH.exe, WW2Mod.dll, SimEngine.dll, ModManager.dll,
CoH build 1647830, Blitzkrieg build 21630206, mod 5.3.7, no loose files. All 257 WW2, 20 Engine, 67 root and
60 DLC files match, as do 113 of the 114 Blitzkrieg files.

The one difference: `Blitzkrieg\Archives\Maps2\6p_RoadToCherbourg_rev2.sga`. It is the same size
(14,489,594 bytes) everywhere, but Player B's SHA-256 starts `6F906D6A` while DESKTOP and PC-C have `BCEDF703`.
Steam reports the same build on all three, so Player B's copy is most likely damaged on disk. No log on any PC
mentions Cherbourg, so it did not cause the logged desync. It would break a game on that map, though, and a bad
sector can mean more damage later. Fix: Steam > Blitzkrieg (681590) > Properties > Installed Files > Verify.
(DESKTOP's copy was rewritten 2026-11-07 by the Steam update/verify, so DESKTOP's copy may have been damaged
before that too.)

## The 2026-05-08 desync, seen from both sides

Map 8p Infantry OP (`1426789716279165026.sga`, identical hash on all three PCs). Players: Player C (1000,
PC-C, host and running both AIs: the AIs are Type 1 on PC-C and Type 3 on Player B), Player B (1003),
CPU-Normal 1004 and 1005, plus empty slots. Sync level 0, SyncErrorChecking Low. Neither player used `-sync_high`.

- PC-C's first mismatch was at 20:47:20.9: CPU 1005's command 54 landed on a 1004 halftrack. 1302 lines followed.
- Player B's first mismatch was at 18:47:53.0 PST, which is about 20:47:56 on PC-C's clock (the disconnect
  timestamps put the clocks about 3 s apart). CPU 1004's command 54 landed on Player B's ranger squad,
  then on 1005's squads (936 times). 1050 lines followed.
- Each PC sees a different CPU's commands landing on the wrong squads. That means the squad-ID-to-owner tables
  of the two simulations had already drifted apart about 31 minutes in. The mismatch lines are a symptom; the
  divergence itself happened earlier and was not detected, because checking was at level Low.
- The host dropped at 20:54:48 to 20:54:51. Player B closed with reason 1004 "disconnected".

What this rules out: different game or mod files (the files and CRC match), different maps, and OneDrive on
Player B's side (Player B has no OneDrive, one adapter, no VPN, and still desynced, so OneDrive and VPN are not
the only cause). The pairing does differ in hardware: an Intel i7-9700KF on Windows 10 (Player B) against an AMD
Ryzen 9 9950X on Windows 11 with Wi-Fi 7 and WireGuard (PC-C). The two clean April games were played on
the same pair, so the hardware alone does not desync every game.
